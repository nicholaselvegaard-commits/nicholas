§ 02

User Flow

Psychology Framework: Jobs-to-Be-Done + Loss Aversion

Every screen is designed around a single emotional driver: "I want to get this job". Loss aversion (the fear of missing out on the role) is activated at the payment wall by showing the finished — but locked — CV.

01
Landing Page — Conversion-Optimised
Above the fold: headline, subheadline, and a single CTA button ("Build My CV Free → Pay Only to Download"). Social proof counter ("47,382 CVs created"). 3 sample CVs across industries rotating as background. No pricing visible yet. Friction-free entry.
UX principle: Zero cognitive load. One action available.
02
Industry & Role Selector — Step 0 (Gate)
Before the full form: "What kind of work do you do?" with 8 clear categories (cards with icons). This single answer sets the AI tone, template style, and question logic for the entire session. Fast selection, big friendly tap targets.
UX principle: Personalization commitment — people finish what they personalize.
03
Multi-Step Questionnaire — 7–12 Steps
Progressive disclosure: each step shows only relevant fields. Progress bar shows completion %. Auto-save to localStorage every keystroke so no data is lost. Estimated time shown: "About 8 minutes". Optional fields clearly labelled. Smart skips for irrelevant sections.
UX principle: Sunk cost + progress momentum. Don't let them leave at 60%.
04
AI Processing Screen — 8–12 Seconds
Animated screen showing what's happening: "Analysing your experience... Rewriting job descriptions... Scoring ATS compatibility... Formatting your layout...". This isn't a loading spinner — it's a value delivery moment. Sets expectation of premium output.
UX principle: Perceived effort = perceived value. Don't make it instant.
05
Preview — Blurred Lock Screen
Show a real, beautifully rendered CV preview — but blurred from 30% down. The name, job title, and summary section are fully visible (positive reinforcement). A floating panel: "Your CV is ready. Unlock it for £4.99." Three trust signals below: Secure payment, Instant download, Yours to keep forever.
UX principle: Loss aversion peak. They can SEE it. They just can't have it yet.
06
Payment — Stripe Checkout
Inline Stripe element (not a redirect). One-click Apple Pay / Google Pay shown first. Order summary restates the value: "1× Professional CV PDF — Instant Download". Optional upsell checkbox: "+ Cover Letter for £2.99". Minimal fields, maximum trust signals.
UX principle: Reduce steps-to-paid to as few as physically possible.
07
Success → Instant PDF Download
Payment confirmed → PDF generated server-side → signed, time-limited download URL (15 min expiry, one-time use) emailed + shown immediately. Upsell for Cover Letter now displayed. Option to create account to save/re-access. Share buttons.
UX principle: Immediate gratification validates purchase decision.
§ 03

Smart Questionnaire Structure

The questionnaire is built on a conditional logic engine. Each step's fields adapt based on: industry chosen, experience level, employment gaps, and previous answers. Below is the complete step structure.

STEP 0Industry & Experience Level Gate
Industry category (card select): Tech / Healthcare / Trade / Corporate / Creative / Education / Hospitality / Other
Experience level: No experience / 1–3 years / 3–10 years / 10+ years / Career change
Role you're applying for (free text with autocomplete)
STEP 1Personal & Contact Information
Full name, professional email, phone, city/country
LinkedIn URL (optional), portfolio/website (optional, shown for creative/tech)
GitHub (shown only if Tech industry selected)
STEP 2Professional Summary Input
What makes you good at your job? (open text — even rough bullet points accepted)
What kind of role are you looking for? (career goal)
Top 3 personal strengths (dropdown + free text)
→ If no experience: replaced with "Tell us about yourself and what you're hoping to achieve"
STEP 3Work Experience (Repeatable Block, up to 5 jobs)
Job title, Company name, Location, Start/End date (or "Present")
What did you do day-to-day? (free text, 3–5 lines)
What did you achieve or improve? (encouraged prompt: "Did you save time, money, grow sales, lead a team?")
Any specific numbers or metrics? (optional but prompted)
→ If "No experience" selected: this step replaced with Volunteer / Personal Projects / School activities
→ Employment gap detection: if gap > 6 months flagged, ask for explanation to handle positively in CV
STEP 4Education
Degree / qualification, Institution, Year (or "In Progress")
Relevant modules, thesis, or notable results (optional)
→ If 10+ years experience: education section moved lower in hierarchy automatically
STEP 5Skills
Technical skills (smart autocomplete library based on industry: e.g. "React, SQL, Python" for tech; "Patient care, ANTT, cannulation" for healthcare)
Soft skills (multi-select: communication, leadership, problem-solving…)
Tools & software (context-aware suggestions)
STEP 6Certifications & Licences
Certification name, Issuing body, Date, Expiry (optional)
→ Trade workers: prompted for CSCS, NVQ, Gas Safe, IPAF etc.
→ Healthcare: DBS check status, NMC pin, first aid certs
STEP 7Languages, Volunteer Work & Projects
Languages spoken + proficiency level (shown always)
Volunteer roles (optional) — title, org, brief description
Projects (shown for tech/creative): project name, tech used, 1–2 line description, URL
STEP 8Preferences & Tone
CV tone: Formal / Confident / Approachable / Bold (auto-suggested based on industry)
Length preference: 1-page / 2-page / Auto (recommended)
Any extra information you want to include?
Dynamic Logic Rules
No experience
Skip work history, expand education, volunteer, and projects. Add transferable skills section. AI tone set to enthusiastic and potential-forward.
Senior / 10+ years
Education moved to bottom. Leadership section added. AI rewrites focus on P&L, team size, strategic impact. Formal, authoritative tone.
Trade worker
Technical skills emphasized first. Certs and licences prominent. Language: direct, practical, no corporate jargon. NVQ/CSCS fields visible.
Career change
Transferable skills section added. AI emphasizes relevance bridges. Personal summary reframed as "bringing X to Y industry" narrative.
§ 04

AI Prompt Engine

This is the core of the product. The system prompt below is what gets sent to the model (Claude or GPT-4o) along with the structured JSON from the questionnaire. It is deterministic, structured, and designed to produce consistently excellent output.

System Prompt — AI CV Writer
You are an expert CV writer and career consultant with 15+ years of experience 
across all industries. Your task is to transform raw user-provided career data 
into a polished, recruiter-ready, ATS-optimised CV in structured JSON format.

═══ CONTEXT ═══
Industry: {{industry}}
Experience Level: {{experience_level}}
Target Role: {{target_role}}
Tone: {{tone}} (formal / confident / approachable / bold)
CV Length: {{cv_length}}

═══ USER DATA ═══
{{serialised_questionnaire_json}}

═══ YOUR JOB ═══

1. PROFESSIONAL SUMMARY (3–4 sentences max)
   - Open with a strong descriptor: "Results-driven", "Dedicated", "Award-winning"
   - State years of experience, industry, and what makes them valuable
   - End with what they're seeking
   - Match tone to industry: formal for corporate, direct for trades, warm for healthcare
   - NEVER start with "I"

2. WORK EXPERIENCE (each role gets 3–5 bullet points)
   - Start every bullet with a powerful action verb (Led, Delivered, Reduced, Built, 
     Designed, Managed, Launched, Resolved, Generated, Implemented...)
   - Rewrite vague duties ("helped with sales") into strong achievement statements
     ("Generated £120K in new business within first 6 months by...")
   - If user provides metrics, use them prominently: numbers, %, £/$, team sizes
   - If no metrics given, write achievement-framed language without fabricating:
     ("Streamlined onboarding process, significantly reducing new staff ramp-up time")
   - Remove all first-person pronouns
   - Remove filler words: "various", "responsible for", "duties included", "helped to"

3. SKILLS
   - Group into: Technical Skills | Tools & Software | Soft Skills
   - Prioritise skills mentioned in the target role description
   - Remove skills that are universally assumed (e.g. "using email", "Microsoft Word" 
     unless the role specifically requires them)

4. EMPLOYMENT GAPS
   - If gap detected: reframe positively and briefly. Examples:
     "Career break — personal development and freelance consultancy (2021–2022)"
     "Sabbatical — carer responsibilities, returned to workforce with updated skills"
   - Never hide or omit gaps; address them professionally

5. EDUCATION
   - If < 5 years experience: place education ABOVE work experience
   - If ≥ 5 years experience: place BELOW work experience
   - Only list graduation year (not start year) unless currently studying

6. ATS COMPLIANCE RULES
   - No tables, no headers in image form, no columns that break ATS parsing
   - Use standard section headings: Experience, Education, Skills, Certifications
   - Avoid graphics, icons, and special characters in the text content fields
   - Use standard date formats: MM/YYYY or Month YYYY

7. TONE CALIBRATION
   - Corporate / Senior: formal, sophisticated, strategic language
   - Trade / Manual: clear, practical, skills-forward, no jargon
   - Healthcare: empathetic, patient-centred language, compliance-aware
   - Tech: concise, technical precision, show-don't-tell
   - Creative: slightly more personality, but professional; no slang
   - Entry-level: enthusiastic, potential-focused, transferable skills highlighted

8. WHAT YOU MUST NEVER DO
   - Never invent job titles, dates, companies, or qualifications
   - Never pad descriptions with meaningless phrases
   - Never exceed the requested page length
   - Never use passive voice ("was responsible for managing")
   - Never leave a section empty if data was provided

═══ OUTPUT FORMAT ═══
Return ONLY valid JSON in this exact schema:

{
  "summary": "string",
  "experience": [
    {
      "title": "string",
      "company": "string", 
      "location": "string",
      "start": "string",
      "end": "string",
      "bullets": ["string", "string", "string"]
    }
  ],
  "education": [{"degree":"string","institution":"string","year":"string","notes":"string"}],
  "skills": {"technical":[""],"tools":[""],"soft":[""]},
  "certifications": [{"name":"string","issuer":"string","date":"string"}],
  "languages": [{"language":"string","level":"string"}],
  "projects": [{"name":"string","description":"string","url":"string"}],
  "volunteer": [{"role":"string","org":"string","description":"string"}],
  "ats_score_estimate": "integer between 70-100",
  "page_recommendation": "1 or 2"
}

Implementation note: Run this prompt with temperature 0.3 for consistent professional output. Use streaming to show live generation on the processing screen. Cache the result server-side against the session ID to avoid re-generation on page refresh.

§ 05

PDF Design Specification

Design Philosophy

The CV must look expensive without looking designed. Recruiters spend 7 seconds on first scan. The layout must guide their eye: name → job title → summary → experience. Every element earns its space or gets cut.

Typography System

Name / H1 — Display
Playfair Display Bold
For the candidate's name only. 26–28pt. Sets tone of premium, trustworthy document.
Fallback: Garamond, Georgia
Section Headers — H2
DM Sans SemiBold — SPACED CAPS
All caps, 9pt, 1.5px tracking. Clean authority without shouting.
Body Text
DM Sans Regular 10pt
Highly legible at small sizes. Bullet points at 9.5–10pt. Line height 1.45.

Layout Grid — Two-Column Structure

Page Architecture

Left sidebar (28% width): Photo (optional), Contact info, Skills, Languages, Certifications, Achievements highlights. Background: very light grey (#f5f5f3) or accent-tinted (#f3f0e8 for gold variant).

Main column (72% width): Name + title at top, Professional Summary, Work Experience (dominant), Education, Projects/Volunteer. Clean white background.

Accent color stripe: 4px left border on section headers. Color adapts by industry: gold (#c9a84c) for corporate; slate blue (#2c4a7c) for healthcare; deep teal (#1a5c5c) for tech; terracotta (#b85c38) for creative.

Section Ordering Logic

Standard (3–10 yrs exp)
Name/Title → Summary → Experience → Skills → Education → Certifications → Languages
Senior (10+ yrs)
Name/Title → Summary → Key Achievements → Experience → Education → Certifications
Entry-level / Graduate
Name/Title → Summary → Education → Projects/Placements → Skills → Volunteer
Trades
Name/Title → Skills & Licences → Experience → Certifications → Education

1-Page vs 2-Page Logic

The AI returns a page_recommendation field. Under 5 years experience = 1 page always. Over 5 years with 3+ jobs = 2 pages. The PDF renderer uses this to automatically scale font sizes (10pt for 1-page, 9.5pt for 2-page) and section spacing. Never force content to fit — a clean 2-page beats a cramped 1-page every time for experienced candidates.

ATS Safety Rules for PDF

Use a text-layer PDF (not image-based). No text inside graphics. No header/footer for section labels (ATS parses linearly). No tables for layout — use absolute positioning or flexbox equivalents in HTML-to-PDF. Standard Unicode fonts. All text extractable via copy-paste test.

Secure Download Logic

Download Flow — Server-Side
1. Stripe webhook fires on payment_intent.succeeded
2. Backend receives webhook → verifies signature
3. Backend triggers PDF generation job:
   a. Fetch session data from DB using session_id from metadata
   b. POST to AI → receive structured JSON
   c. Render HTML CV template with JSON data
   d. Puppeteer screenshots → generates PDF buffer
   e. Upload to R2: cv/{orderId}/cv.pdf
   f. Generate signed URL: expires in 15 minutes, single-use token
4. Store order in DB: { orderId, email, sessionId, downloadUrl, paidAt }
5. Send email via Resend: "Your CV is ready → [Download Now]"
6. Redirect user to success page with immediate download button
7. Download endpoint verifies token, marks as used, streams PDF

§ 08

7-Day MVP Plan

The MVP strips everything to the core value loop: answer questions → AI generates CV → pay → download. No accounts. No upsells initially. No fancy animations. Ship it.

Day 1
Project Setup + Landing Page
Next.js + Tailwind scaffold. Deploy to Vercel. Build landing page with headline, CTA, and "how it works" section. Set up Supabase, R2 bucket, Stripe account.
Day 2
Multi-Step Form (Steps 0–4)
Build the questionnaire UI: industry picker, personal info, work experience (up to 3 jobs), education. React Hook Form + localStorage auto-save. No conditional logic yet — add all fields.
Day 3
Multi-Step Form (Steps 5–8) + AI Integration
Skills, certifications, preferences steps. Build API route: serialize form → send to Claude API with system prompt → receive JSON response. Handle errors, stream response if possible.
Day 4
PDF Generation + Preview
Build HTML CV template. Wire Puppeteer (or react-pdf) to render AI JSON to PDF. Build preview screen: show first section visible, blur rest. Upload PDF to R2.
Day 5
Stripe Integration + Payment Wall
Stripe Payment Intent + inline checkout UI. Webhook handler: on success → generate signed URL → save to DB. Success page with download button. Test end-to-end with Stripe test mode.
Day 6
Email Delivery + Polish
Wire Resend to send download email on payment. Add loading/processing screen. Error states. Mobile responsiveness. Basic SEO meta tags. Test complete user journey 10 times.
Day 7
Launch
Bug fixes from Day 6 testing. Set up PostHog analytics. Switch Stripe to live mode. Write 3 social posts. Post on Reddit (r/jobs, r/GetEmployed), Product Hunt, LinkedIn. Ship it.
What's NOT in the MVP

Deliberately excluded from MVP: user accounts and login, conditional form logic, multiple CV templates, cover letter generator, upsells, subscription model, admin dashboard, CV editing after generation. All of these are real features — but none of them are required to make the first sale. Build the core loop first. Every other feature should be unlocked only once someone pays.

The MVP Bet

You are betting that people will pay £4.99 for an AI-written CV delivered instantly. This bet is testable in 7 days with one developer and ~£50 in infrastructure. If the first 20 paying customers arrive, the product works. Then add features based on what real users ask for — not what you imagine they want.
